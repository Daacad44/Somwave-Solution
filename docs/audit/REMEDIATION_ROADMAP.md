## Principles

- Phases run in order A, B, C, D, E. Phase E tasks that only add tests or CI steps (E1, E2, E5) can start in parallel with Phase A, because they protect the fixes made there.
- Each task is a vertical slice that follows CLAUDE.md §3 and §15: shared schema, migration, service, controller/route, frontend, test, staging deploy. Keep each pull request under 400 lines and split by task.
- A task is done when its acceptance criteria are met on staging with authenticated tests. Code merged without the test is not done.
- Complexity: S = up to a day, M = a few days, L = a week or more (as estimated by the auditing agents).
- Risk is the delivery risk of the change itself (what could break), not the risk of the finding.

### Note on image storage

Image storage is being re-platformed onto ImageKit in a separate change (`feat/imagekit-media-storage`), at the user's request. Once it is configured in production, that change addresses the "Image storage is unavailable" findings (SW-005, and the filesystem durability finding SW-054). It was not reviewed in this audit. The nginx `client_max_body_size` finding (SW-004) **still applies**, because uploads continue to pass through the app's same-origin nginx proxy. Task B2 below should therefore be read as "finish and verify the ImageKit change, plus fix nginx".
