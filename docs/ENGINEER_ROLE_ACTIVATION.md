# Engineer role and account activation

The `ENGINEER` role was previously created by `prisma/seed.ts` only. A production database that applied migrations without that seed could therefore lack the role, while the Roles & Permissions page correctly displayed only the seven rows that existed. The additive `20261014020000_ensure_engineer_system_role` migration creates the canonical system role if absent, marks it as a system role, supplies its description, and grants the nine permissions required for the engineering workspace and project-scoped work. Its `ON CONFLICT` clauses avoid duplicate roles or grants. Existing users, invitations, administrator roles, and manually assigned ENGINEER permissions are preserved. The production entrypoint applies pending migrations before starting the API.

New passwords must contain 12–128 characters, uppercase and lowercase letters, a number, and a special character. The API rejects obvious name/email fragments and matches against an offline corpus of roughly 49,000 common passwords. The offline check does not need external network access; it cannot guarantee detection of every breached password. New passwords use Argon2id with no 72-byte truncation. Existing bcrypt hashes continue to work at login and when an existing account accepts the engineer role; that flow checks the current password without imposing the new creation policy. Account creation and password reset use the same new-password policy. Existing sessions and the Super Admin role are not changed.

The activation form shows live requirements, strength and mismatch feedback, permits paste and password managers, and sends a confirmation field for new accounts. A failed validation leaves the activation token usable. After activation, the sign-in link returns the engineer to `/engineering`. Project membership is still required to see a project; merely holding the ENGINEER role does not expose other projects.

Before production deployment, back up the database and review the migration. After the Coolify deployment, confirm that ENGINEER appears under Roles & Permissions, activate a designated test engineer through an invitation, sign in, and verify the Engineering Workspace and project isolation. This workspace cannot inspect the Coolify database or perform a live mailbox activation, so those checks remain pending until deployment access is available.
